# django-learning — phase-1 branch

This branch is a snapshot of Phase 1 from `django-learning-roadmap.md`: orientation on plain Django with SQLite, before any of the real onboarding-platform work begins. It follows [Part 1](https://docs.djangoproject.com/en/6.0/intro/tutorial01/) and [Part 2](https://docs.djangoproject.com/en/6.0/intro/tutorial02/) of the official Django polls tutorial. Parts 3 and 4 (templates, forms) were skimmed but not built, so there are no templates and the view returns a plain `HttpResponse`.

It is a standalone learning artifact, not related to the onboarding platform described in the repository's main `CLAUDE.md`. No Docker, no PostgreSQL, no DRF, no Celery: just `django-admin startproject`, `startapp`, models, migrations, and the admin site.

## What's here

- `mysite/` — the Django project (settings, root URLconf, WSGI/ASGI entrypoints).
- `polls/` — the one app created in the tutorial, with:
  - `models.py` — `Question` and `Choice` models with a `ForeignKey` and a `was_published_recently` helper.
  - `admin.py` — both models registered with the Django admin.
  - `views.py` — a single `index` view returning plain text.
  - `urls.py` — the app's URLconf, included from `mysite/urls.py` under `/polls/`.
  - `migrations/0001_initial.py` — generated by `makemigrations`, not hand-written.
- `db.sqlite3` — the SQLite database used for this phase.
- `manage.py` — Django's command-line utility.

## Prerequisites

- Python 3.8+
- pip

## Setup

1. Clone the repo and check out this branch:

    ```bash
    git clone <repo-url>
    cd django-learning
    git checkout phase-1
    ```

2. Create and activate a virtual environment:

    ```bash
    python -m venv .venv
    ```

    Windows PowerShell:

    ```powershell
    .venv\Scripts\Activate.ps1
    ```

    macOS / Linux:

    ```bash
    source .venv/bin/activate
    ```

3. Install Django:

    ```bash
    pip install django
    ```

4. Apply migrations and create a superuser:

    ```bash
    python manage.py migrate
    python manage.py createsuperuser
    ```

5. Run the development server:

    ```bash
    python manage.py runserver
    ```

6. Visit `http://127.0.0.1:8000/polls/` for the index view and `http://127.0.0.1:8000/admin/` for the admin site.

## Notes

- `SECRET_KEY` is the placeholder value Django generates on `startproject`. It is fine for this throwaway phase but should never be committed for a real project.
- There is no `requirements.txt` yet since Django is the only dependency installed so far.
